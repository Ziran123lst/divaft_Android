# 原生策略：native-first + AOT 渐进

目标：让游戏运行尽可能原生。把"原生"拆层看：

## 已经原生的部分（运行大头）

| 层 | 实现 | 原生? |
|---|---|---|
| 系统库 HLE | 原生 ARM64 重写 | ✅ |
| 渲染器 | shadPS4 → 原生 Vulkan | ✅ |
| 音频 | Ngs2 → 原生 AAudio | ✅ |
| 输入 | 触屏 → 原生事件 | ✅ |

音游关键路径（渲染/音频/输入）全原生，这是 60fps + 低延迟的根本。

## 游戏代码层：翻译的原生程度

游戏是 x86-64，手机是 ARM64，必须翻译。两种方式：

| 方式 | 原理 | 原生程度 |
|---|---|---|
| FEX JIT | 运行时翻译 x86→ARM64，缓存后执行 | 翻译后**即原生 ARM64 执行**，开销在首次翻译+调度 |
| AOT 静态重编译 | 提前翻译，直接跑 | 几乎零翻译开销，最原生 |

关键认知：FEX 翻译后的游戏代码本来就是原生 ARM64 在执行，不是解释执行。
AOT 只是把翻译从运行时挪到提前。

## AOT 的难点（诚实）

完整 PS4 游戏做 AOT 难：自修改代码、间接跳转、代码数据混杂，AOT 难以完全覆盖。
这是研究前沿（gow3 的 AOT 支线未合并、uncharted lift/remill 停在研究）。是目标非保票。

## 本项目的策略

1. 运行时做成 **AOT 友好**：翻译层与执行层干净分离。
2. 先 **FEX JIT 跑通**（可靠基线，翻译后已原生执行）。
3. **AOT 渐进**：热点/稳定路径静态重编译，动态部分（SMC/间接跳转）回退 JIT，逐步逼近全原生。

起步可靠，又保留"尽可能原生"的上升通道。
